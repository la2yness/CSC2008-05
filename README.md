# Theme Park Route Planner

테마파크에서 "실시간 대기시간과 방문객 유형"을 고려하여, 여러 어트랙션을 순회하는 경로를 찾는 시스템

------------------------------------------------------------------------

## 1. 문제 개요

-   **설계자 입력**
    -   실제 테마파크 지도를 기반으로 한 고정 그래프
        -   노드: 어트랙션 / 편의시설 등
        -   간선: 각 노드 간 이동 경로
    -   각 어트랙션의 실시간 대기시간 정보
-   **사용자 입력**
    -   방문객 정보 (키, 나이 등)
    -   가고 싶은 어트랙션 리스트 (원하는 노드 집합)
-   **출력**
    -   방문객 제약조건을 만족하면서,
    -   선택된 어트랙션 리스트를 가능한 한 많이/모두 순회하는
    -   가중치 기반 최적 경로
-   **목표**
    -   단순 최단거리가 아니라 이동시간 + 대기시간 등을 포함한 가중치 수식을 최소화
    -   여러 어트랙션을 방문하는 순서/동선 알고리즘을 설계
    -   서로 다른 알고리즘들의
        -   가중치 기준 성능
        -   실행시간
        -   메모리 사용량 을 비교·분석

------------------------------------------------------------------------

## 2. 그래프 모델

### 2.1 노드

-   **각 노드는 하나의 어트랙션 또는 편의시설(입구, 식당, 화장실 등)을 의미**
-   노드 `v`에 대한 속성:
    -   `id`: 0..N-1 (정수 인덱스)
    -   `type`: attraction / entrance/ restaurant / restroom ...
    -   `wait_time[v]`: 현재 또는 특정 시점에서의 예상 대기시간
    -   `constraints[v]`: 최소/최대 키, 최소/최대 연령 등의 탑승 조건
-   사용 가능 / 불가능 처리
    -   방문객 프로필이 주어졌을 때:
        -   `is_usable(v, user_profile) -> bool`
        -   조건을 만족하지 않는 노드는 끄기
    -   가고 싶은 어트랙션 리스트 S가 주어졌을 때:
        -   S에 포함된 노드는 켜기, 포함되지 않은 노드는 끄기
    -   공원의 모든 어트랙션을 순회하고 싶을 때:
        -   단순히 S = (모든 노드 집합) 으로 설정

### 2.2 간선

-   **간선 `(u, v)`는 실제 이동 가능한 경로를 의미**
-   간선 속성:
    -   `move_time[u][v]`
-   내부 표현:
    -   인접 리스트: `adj[u] = [(v, move_time_uv), ...]`
-   중요 가정
    -   공원 구조(노드/간선, 거리)는 시간에 따라 변하지 않는 고정 그래프
    -   실시간으로 변하는 것은 노드의 대기시간 정보
    -   무방향 그래프

------------------------------------------------------------------------

## 3. 가중치 수식

**각 이동 단계 `(u → v)`에 대해, 이동시간 + 대기시간을 반영한 비용을 정의**

-   기본 형태:

        cost(u → v) = α * move_time(u, v) + β * wait_time(v, t)

    -   `α, β`: 가중치 계수
    -   `wait_time(v, t)`: 시점 `t`에서의 v의 대기시간

-   전체 경로 `P = (v0, v1, ..., vk)`의 총비용:

        total_cost(P) = Σ cost(vi → v{i+1})

------------------------------------------------------------------------

## 4. 사용자 입력 및 제약조건 처리

1.  **방문객 프로필**
    -   `user_profile = { age, height, ... }`
    -   `is_usable(v, user_profile)`:
        -   키/연령 조건 위반 시 `False`
        -   아니면 `True`
2.  **원하는 어트랙션 리스트**
    -   `desired_set = { v1, v2, ..., vk }`
    -   알고리즘 실행 시:
        -   켜진 노드 = `desired_set ∩ { v | is_usable(v, user_profile) }`
    -   이 집합 안의 노드들을 가능한 한 많이/모두 방문하는 최적 경로를 찾는 것이 목표
3.  **그래프 필터링**
    -   노드 필터:
        -   `usable[v] = is_usable(v, user_profile) and (v in desired_set)`
    -   간선 필터:
        -   `(u, v)`를 사용할 때, `usable[u]`, `usable[v]` 둘 다 True인 경우에만 고려

------------------------------------------------------------------------

## 5. 다수 어트랙션 순회 알고리즘 (Route Planning Algorithms)

여기서는, 어트랙션 순서 결정 알고리즘들을 비교 대상으로 선정한다\
각 알고리즘은 노드 순서를 결정하고, 각 구간의 실제 비용은 `edge_cost`와 단일경로 알고리즘을 통해 계산한다고 가정한다

### 5.1 공통 하위 계층: 구간 비용 계산

-   목적: 두 어트랙션 `i`, `j` 사이의 최소 이동시간을 미리 구해두기.
-   방법:
    -   고정 그래프에 대해 "이동시간만"을 가중치로 사용하는 최단경로를 미리 계산한다

        -   모든 노드에 대해 Dijkstra → `O(V * (V+E) log V)`

    -   결과:

        -   `travel_cost[i][j] = 최소 이동시간`

    -   이후 상위 알고리즘에서는

            leg_cost(i, j) = α * travel_cost[i][j] + β * wait_time[j] 처럼 사용한다

------------------------------------------------------------------------

### 5.2 알고리즘 1: Greedy Nearest-Next

-   개념:
    -   현재 위치에서, 아직 방문하지 않은 "사용 가능 노드"들 중
        -   `leg_cost(current, candidate)`가 최소인 노드를 다음 방문지로 선택한다
    -   이를 방문할 때마다 현재 위치를 갱신하면서 반복한다

------------------------------------------------------------------------

### 5.3 알고리즘 2: Greedy Nearest-Next + 2-Opt Local Search

-   개념:
    1.  위의 Greedy Nearest-Next로 초기 경로를 생성한다
    2.  그 후, 2-opt 개선을 수행한다:
        -   경로 상의 두 구간 `(i, i+1), (j, j+1)`을 선택하여
        -   이 구간 사이의 순서를 뒤집었을 때 총 비용이 줄어들면 교환한다
    3.  더 이상 개선되지 않을 때까지 반복한다

------------------------------------------------------------------------

### 5.4 알고리즘 3: Cheapest Insertion Heuristic

-   개념:
    1.  시작 노드로 초기 경로 구성한다
    2.  아직 포함되지 않은 노드를 경로 중 가장 비용 증가가 작은 위치에 삽입한다
    3.  모든 노드가 포함될 때까지 반복한다

------------------------------------------------------------------------

### 5.5 알고리즘 4: Random Baseline

-   무작위 순열 기반 경로를 생성한다
-   다른 알고리즘들의 성능 비교를 위한 기준선 역할을 하도록 할 예정이다

------------------------------------------------------------------------

## 8. 제약사항 및 가정

-   그래프 구조는 고정
-   move_time ≥ 0 (Dijkstra 사용 가능을 위함)
-   wait_time은 실행 시점에서 고정된 값으로 근사
-   방문객의 조건은 이진으로 판단
-   규모 K는 Greedy/Local Search가 적용 가능하다고 가정

## 11. 구현 세부사항

### 11.1 파일 설명

-   `graph.py`: 그래프 자료구조 및 노드 정의
-   `weights.py`: 가중치 계산 함수 정의
-   `user.py`: 사용자 프로필 및 제약조건 정의
-   `routing/leg_shortest_path.py`: Dijkstra 기반 최단 경로 사전 계산
-   `routing/alg_greedy_nearest.py`: 탐욕적 최근접 이웃 알고리즘
-   `routing/alg_greedy_2opt.py`: 2-opt 지역 탐색을 적용한 탐욕 알고리즘
-   `routing/alg_cheapest_insertion.py`: 최소 비용 삽입 휴리스틱 알고리즘
-   `routing/alg_random_baseline.py`: 무작위 경로 생성, 기준선 알고리즘
-   `evaluation.py`: 성능 평가
-   `main.py`: 메인 실행 파일

### 11.2 알고리즘 시간 복잡도

-   **최단 경로 사전 계산**: O(V * (V+E) log V) - 모든 노드 쌍에 대해 Dijkstra 실행
-   **Greedy Nearest-Next**: O(K²) - K개의 목표 노드에 대해 순차적으로 최근접 선택
-   **Greedy + 2-Opt**: O(K² + I*K³) - 초기 경로 + I번의 2-opt 반복 (각 스왑마다 O(K) 구간 재계산)
-   **Cheapest Insertion**: O(K² * K) = O(K³) - K번의 삽입, 각 삽입마다 K개 위치 탐색
-   **Random Baseline**: O(K) - 노드 리스트 셔플만 수행
